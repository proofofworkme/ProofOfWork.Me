# Explicit verification-only identity qualification

This opt-in contract does not redefine artifact source or make exact-HEAD
release synchronization pass. The default check-release-sync.mjs is unchanged.
An artifact built from 064 remains artifact 064. The operator comparison baseline is c7;
the current operator revision is the committed verifier actually executed.
The accepted node runtime overlay is 609; its retained archive contains an
earlier base release plus accepted overlays. These identities are not synonyms.

## Authority and evidence

The identity proof checks fixed reviewed commits and trees, exact historical
verification-only deltas, and exhaustive equality of all other tracked paths,
types, modes and Git blobs. The implementation delta is separately constrained
to reviewed verification files. The actual executable closure must be canonical
and match the committed implementation; dirty source, hidden index flags,
unexpected package scopes and Node preload overrides refuse.

A proof is an immutable process-local branded value, not JSON authority.
Original sealed build receipts, archives and UI/renderer provenance are never
rewritten. Protected preactivation executes the unchanged four pinned modules
from the original artifact's clean build checkout. Its receipt keeps that
artifact identity; an explicit wrapper records who verified it.

Offline hash-pinned evidence consistency checking is not live qualification.
A caller-supplied matching digest establishes byte identity, not authenticity
or current production health. Offline results carry liveCollectionVerified=false
and cannot satisfy the retained-writer-off schema. Live qualification requires
the separately branded hardwired collector, fresh observations, source fences
and immutable reviewed evidence anchors. Arbitrary JSON and injected transports
cannot mint collection authority.

Original native/browser execution identities and execution-time uncertainty
must remain truthful. Reading an old test result today is not a new test run.
Where applicability follows unchanged product bytes, retain the original
subject and explicit equivalence proof. Never invent timestamps from mtimes
or retrofit historical receipt fields. Live observations have a 15-minute bound.
Missing reviewed archival authority or required current checks fails closed.

The separate Python writer-off schema requires a trusted qualification digest
from independently reviewed collector output, not a report's own digest or
arbitrary user JSON. JSON cannot carry a JavaScript brand. The schema cross-binds
original UI, renderer, runtime archive, native/browser and preactivation artifacts
and always returns activationAllowed=false.

## Scope and reversibility

No publication, manifest relabel, retention cycle, signing, transaction,
database rewrite or writer activation is performed. Existing artifact and
rollback obligations remain intact. Withdrawal means refusing qualification,
not editing deployed provenance or deleting history. Owner acceptance of dual
identity is separate from engineering validation and writer authorization.

## Testing

Default exact-sync remains byte-identical and rejects mismatched HEAD.
Tests reject forged brands, unexpected deltas/executable inputs, changed
receipts, missing surfaces, stale/future live evidence, wrong original subjects,
changed runtime/readiness/retention guards and offline receipt promotion.
Positive branded Git/probe tests run only after a local candidate commit;
no test-only production identity mint exists. Synthetic tests do not establish
production qualification.

## Execution identity and primary alignment

The comparison baseline remains c7cfa32. The separately reviewed, committed
verification implementation is the current operator identity D, not another
artifact identity. Future authorized use requires GitHub main and the existing
primary checkout to equal D. The existing preview and production surfaces must

The ordinary exact-HEAD release check remains unchanged and does not accept this
intentional operator/artifact split. Package, lockfile, build config and all
production modules remain identical to the compared released product.

## Sealed-source Git ownership

Protected artifact source may legitimately belong to powadmin rather than root.
The collector checks canonical ancestor, source, Git metadata and checker paths,
permits only the verified root or powadmin account, and pins the original sealed
Git configuration. It runs only four explicit read-only Git command forms as
that owner through fixed runuser with a cleared environment. Before/after
metadata fences reject replacement or mutation. This does not add safe.directory
exceptions, change ownership or permissions, or relax source cleanliness.
The failed original collection remains evidence, not a success receipt.

## Bounded failure diagnostics

A failed protected probe emits only the fixed publish-linked-remote-failure-v1
schema. Known check names retain true, false or null; omitted checks are not
reported as failures. Unknown names and arbitrary checker errors are never
copied. Child stdout is capped at 2 MiB while excess bytes are drained and
discarded; stderr is discarded. The public diagnostic is capped at 16 KiB and
accepts only canonical JSON, fixed classifications, bounded numbers and exact
request identities. It contains no environment values, protected token, raw
error/stderr or digest of secret-bearing raw output.

sourceFenceVerified: false means the post-probe source fence was **not
verified**, not that the source changed. Failed probes skip that expensive fence
to reserve time for terminal reconciliation. A successful receipt still requires
the original source and build-receipt fences. outcome: uncertain requires
reconciliation of the named transient unit before retry; even a verified stopped
failure is never a successful qualification or permission to retry. Failure
diagnostics cannot recover the cause of an earlier discarded probe output.

## Same-collection two-pass lifecycle verification

The explicit collector performs two complete stock lifecycle status scans, before
and after the other read-only probes. The activity probe alone may consume the
first scan through an immutable process-local witness bound to the exact branded
source proof and one collection. JSON, cloned handles, stale witnesses and reused
or superseded witnesses cannot substitute. Standalone/default activity still
runs its own complete lifecycle status.

Activity labels this reuse provisional: the final independent full scan remains
required. Qualification compares the entire stock status, including context,
guards, manifests, holds, capacity authority, controller/config/state/index
bindings and completion history. No status fields are treated as volatile or
omitted. Only the separately reconstructed source proof's observation timestamp
is excluded from source equality. Source identities and closure hashes remain
exact. The original 900-second collection budget is unchanged and the witness
also checks wall and monotonic age. Failure burns the consumed/finalized witness;
a new collection is required, not an automatic probe retry.

Tests use isolated synthetic transports and identity brands, including the real
activity control flow. They do not establish production qualification, retirement,
deployment, or writer activation.


## Capability scheduler test observation correction

The HTTP workflow regression observes each probe at its first marker callback,
not at the later source fence after awaited health, Search and chain work. A slow
first health read can legitimately place consecutive source fences less than one
second apart even when probe entries remain one second apart. The real HTTP
entry-spacing assertion keeps its existing 999 ms threshold, four fresh reads,
source-drift rejection and signed-receipt preservation checks. An isolated mocked
clock regression proves a 250 ms first health delay yields 1,000 ms entry spacing
but only 750 ms between source observations, and refuses a new entry at 999 ms.

This is a test-observation correction, not a scheduler change or proof that wall
clock changes cannot affect production timing. Production scheduler/product
bytes, package/lock, pinned probe closure, writer state and live data are unchanged.

The edited server test is included in the recursive operational source envelope if deployed: the operator envelope therefore must not be equated to artifact064/backend609. This candidate is operator-only; never copy its server tree into live runtime or relabel original source receipts. Dual qualification continues reading the original sealed064 source and accepted609 runtime independently.


## Explicit historical-payload retirement successor

The legacy in-place 1042/c396 hold branch is unchanged. An alternative requires
the exact reviewed retirement terminal, retained sidecars/history, original
064/e266 pair and authenticated later lineage. It does not accept missing
payloads or a success boolean as evidence.

Before either full lifecycle scan executes successor policy, the collector
authenticates every member of the fixed operator package against the qualified
operator Git commit/tree and canonical package-manifest hash. Artifact064
provenance remains separate. Both scans bind the complete lifecycle status and
package attestation; the middle activity witness remains provisional until the
independent final scan matches.
